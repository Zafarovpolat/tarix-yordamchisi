# Tarix yordamchisi — версия с Groq

## Обновление этой версии (правки по замечаниям клиента)

Исправлены две вещи, о которых вы написали:

1. **Аватар теперь женский — под женский голос.** Раньше модель была мужской,
   а голос женский — было несоответствие. Поставил женский 3D-аватар
   Ready Player Me (`models/avatar.glb`), он к тому же лучше проработан (волосы,
   плечи, одежда) вместо прежней «голой» головы. Липсинк перенастроен на новую
   модель: рот, зубы и глаза у неё — отдельные меши, и анимируются они все
   синхронно, поэтому губы двигаются естественно.
2. **Голос отвечает быстрее.** Задержку давал «холодный» первый запрос к
   бесплатному сервису озвучки — установка соединения занимала несколько секунд.
   Сделано две вещи: (а) при загрузке страницы озвучка «прогревается» тихим
   фоновым запросом, поэтому первый ответ уже не ждёт установки соединения;
   (б) длинный ответ озвучивается по предложениям — аватар начинает говорить,
   как только готов первый кусок, а не после синтеза всего ответа целиком.

### Про аватар и лицензию (важно перед публичным запуском)
Сейчас в проекте — бесплатный демо-аватар Ready Player Me. Для показа он
подходит полностью, но у стоковой RPM-модели лицензия **CC BY-NC**
(некоммерческое использование). Для публичного/коммерческого запуска
сгенерируйте **свой** бесплатный аватар на https://readyplayer.me (2–3 минуты,
по фото или из конструктора), скачайте `.glb` и просто положите его вместо
`models/avatar.glb`. «Риг» (набор блендшейпов) у всех RPM-аватаров одинаковый,
поэтому липсинк заработает без единой правки в коде. При другом имени файла
поменяйте одну строку в `index.html`: `const MODEL_URL = 'models/avatar.glb'`.

## Что внутри
- `index.html` — фронтенд: голосовой ввод, ответ голосом, **3D-аватар с
  липсинком** (новое) и обращения к серверным функциям ниже
- `netlify/functions/answer.js` — серверная функция ответов: сначала проверяет
  базу фактов школьной программы, при отсутствии совпадения — ищет статью
  в Wikipedia и просит модель Groq ответить строго по её содержимому
- `netlify/functions/tts.js` — **серверная функция озвучки** (новое):
  синтезирует речь бесплатным нейро-голосом Microsoft Edge Read-Aloud и отдаёт
  mp3 со своего домена. Нужна для узбекского голоса и для настоящего липсинка
  по амплитуде (см. раздел ниже)
- `netlify/functions/facts-db.json` — проверенная база фактов (см. ниже)
- `models/avatar.glb` — 3D-аватар (женский, Ready Player Me) с ARKit-блендшейпами для липсинка
- `three/basis/` — локальный декодер текстур модели (basis/KTX2)
- `netlify.toml` — говорит Netlify, где искать функции

## 3D-аватар и озвучка (что нового)

К уже работавшему приложению добавлены две вещи, которые просил клиент:
**говорящий 3D-аватар** и **настоящий липсинк** (губы двигаются в такт речи).

### Как это работает
- Аватар — 3D-модель (`models/avatar.glb`, женский персонаж Ready Player Me)
  на Three.js. Библиотека Three.js подгружается с CDN (jsdelivr) прямо в
  браузере — сборка не нужна, деплой остаётся простым перетаскиванием папки.
- Озвучка идёт через свою функцию `tts.js`: она синтезирует речь нейро-голосом
  Microsoft Edge Read-Aloud (тот же движок, что Azure Neural TTS — звучит
  «человечно») и отдаёт mp3 с вашего домена. Это решает сразу две задачи:
  1. **Узбекский голос.** Браузерный синтезатор речи почти нигде не умеет
     говорить по-узбекски, и бесплатный Google Translate TTS его тоже не умеет
     (проверено). Умеет Edge — голос `uz-UZ-MadinaNeural` (раньше узбекский был
     только текстом). Русский озвучивается голосом `ru-RU-SvetlanaNeural`.
  2. **Липсинк.** Раскрытие рта считается по реальной громкости звука; для
     этого аудио обязано приходить с того же домена (ограничение браузера) —
     ровно поэтому нужна своя функция-прокси, а не прямой запрос наружу.

### Что будет, если что-то недоступно (резервные пути)
Всё сделано так, чтобы сайт работал, даже когда часть возможностей недоступна:
- **Нет WebGL / не загрузился Three.js** → вместо 3D показывается прежняя
  буква «Т», остальное работает как раньше.
- **Функция `tts.js` недоступна** (нет сети, локальный запуск через `file://`,
  оба облачных источника закрыты) → озвучка автоматически откатывается на
  встроенный браузерный голос; для русского это работает, губы двигаются по
  приблизительным «виземам».
- **Только для русского** есть ещё промежуточный резерв: если нейро-голос Edge
  вдруг не ответил — функция сама добирает звук через бесплатный Google
  Translate TTS, и клиент ничего не замечает.
- **Узбекского браузерного голоса нет и облачный недоступен** → ответ честно
  показывается только текстом, без звука.

### Про озвучку и деньги
`tts.js` использует бесплатный нейро-голос Microsoft Edge Read-Aloud (без ключа
и без карты) — дополнительных затрат он не создаёт, это осознанный выбор ради
«максимально дёшево». Для русского есть бесплатный резерв Google Translate.
Ключ Groq к озвучке отношения не имеет. Эндпоинты недокументированные и
теоретически могут закрыться — тогда сработает браузерный резерв выше, а для
стабильного прод-звука в `tts.js` можно позже подставить платный neural-TTS
(Azure / Google Cloud): интерфейс функции (принимает `{text, lang}`, отдаёт
`audio/mpeg`) менять не придётся, фронтенд трогать не нужно.

## База фактов школьной программы (facts-db.json)

**Важно:** записи в этом файле сейчас — демонстрационные примеры, они НЕ
являются официально утверждённым Минобрнауки контентом, хотя фактическая
точность проверена по общедоступным источникам. Перед реальным
использованием в школах каждую запись должен проверить и утвердить
методист/историк на основе настоящего учебника.

### Формат записи
```json
{
  "id": "уникальный-идентификатор",
  "grade": "класс, например 7",
  "topic_ru": "Название темы на русском",
  "topic_uz": "Название темы на узбекском",
  "keywords_ru": ["ключевые слова", "варианты формулировки вопроса"],
  "keywords_uz": ["xuddi shu, o'zbek tilida"],
  "answer_ru": "Готовый ответ на русском, 2-4 предложения",
  "answer_uz": "Xuddi shu javob o'zbek tilida",
  "photo_url": "ссылка на изображение (можно оставить пустой строкой)",
  "source_ref": "ссылка на учебник/страницу/раздел программы — для проверки"
}
```

### Как работает поиск совпадений
Вопрос ученика сравнивается с полем `keywords_ru`/`keywords_uz` каждой
записи (простое совпадение по вхождению слов, без ИИ и без сторонних
библиотек). Чем больше ключевых слов совпало — тем выше запись в приоритете.
Если совпадений нет вообще — вопрос уходит по резервному пути через
Wikipedia + Groq, как раньше.

**Важно для качества совпадений:** в `keywords_ru`/`keywords_uz` стоит
включать не только само название темы, но и то, как **реально** может
прозвучать вопрос ученика — разговорные формулировки, синонимы, возможные
ошибки распознавания речи.

### Как добавить реальные темы
1. Возьмите тему из утверждённой программы (например, календарно-тематический
   план вашей школы/Минобрнарода)
2. Сформулируйте краткий ответ на русском и узбекском в 2-4 предложения —
   максимально близко к формулировке учебника
3. Добавьте новую запись в `facts-db.json` по образцу выше
4. Передеплойте — новые темы сразу заработают, ничего в коде менять не нужно

Файл можно редактировать хоть вручную, хоть попросить меня перенести туда
содержимое из вашего Excel/Word с темами программы — пришлите файл, и я
структурирую его в этот формат.

## Как развернуть

### 1. Получить API-ключ Groq (бесплатно, без карты)
1. Зарегистрироваться на https://console.groq.com
2. Создать ключ в разделе **API Keys** (кнопка «Create API Key»)
3. Скопировать ключ — он показывается один раз и начинается на `gsk_...`.
   Ни баланса, ни привязки карты не нужно: у Groq есть бесплатный тариф
   с лимитом запросов в минуту

### 2. Задеплоить на Netlify
Перетащите всю эту папку (не отдельные файлы, а именно папку целиком, со
всей вложенной структурой `netlify/functions/...`) на страницу Deploys
вашего существующего сайта `tarix-yordamchisi`, либо на
https://app.netlify.com/drop для нового сайта.

Ассеты аватара (`models/`, `three/`) и функция озвучки `netlify/functions/tts.js`
уезжают на сервер **автоматически** вместе со всей папкой — ничего отдельно
заливать или настраивать не нужно.

Если после перетаскивания функция не появилась (Netlify иногда не подхватывает
функции при обычном drag-and-drop) — используйте Netlify CLI, это надёжнее:
```bash
npm install -g netlify-cli
netlify login
netlify deploy --prod
```
Запускать из этой самой папки.

### 3. Задать переменную окружения с ключом
**Обязательный шаг** — без него ступень «умных» ответов будет отвечать
ошибкой (база фактов при этом продолжит работать и без ключа):
1. В Netlify: **Site configuration → Environment variables → Add a variable**
2. Имя: `GROQ_API_KEY`
3. Значение: ваш ключ (начинается на `gsk_...`)
4. Сохранить, затем **передеплоить сайт** (Deploys → Trigger deploy),
   чтобы функция подхватила новую переменную

### 4. Проверить
Откройте сайт, задайте вопрос по истории — теперь ответ формирует модель Groq
на основе найденной статьи Wikipedia, а не просто вступление статьи целиком.

## Важно про стоимость и лимиты
Groq на бесплатном тарифе не берёт денег за запросы — каждый «умный» ответ
(тот, что идёт через Wikipedia + Groq, а не из базы фактов) бесплатен. Взамен
у бесплатного тарифа есть лимит запросов в минуту и в сутки: для презентации
и небольшого класса этого достаточно, но при массовом одновременном
использовании часть запросов может упереться в лимит — тогда сработает честный
откат «ответ только текстом». Если понадобится снять лимиты, у Groq есть
платный тариф с тем же ключом и без изменений в коде.

## Защита от злоупотреблений

Хорошая новость: неожиданного денежного счёта здесь быть не может — Groq на
бесплатном тарифе не тарифицирует запросы. Максимум, что грозит при
злоупотреблении, — исчерпание бесплатного лимита запросов, после чего сайт
честно откатывается на «ответ только текстом», ничего не ломая.

Функция всё же публична по адресу `/.netlify/functions/answer` — теоретически
кто угодно может слать туда запросы напрямую, в обход интерфейса, и «съедать»
ваш дневной лимит Groq. Защита от этого:

### Общий токен между фронтендом и функцией (опционально)
Один и тот же токен теперь прикрывает **обе** функции — и `answer.js` (ответы),
и `tts.js` (озвучку). По умолчанию отключено. Чтобы включить:
1. В `index.html` замените значение токена в **двух** местах (значения должны
   совпадать):
   - в запросе за ответом: `'x-app-token': 'tarix-2026-demo'`
   - в озвучке аватара: `const APP_TOKEN = 'tarix-2026-demo'`
2. В Netlify → Environment variables добавьте `APP_SHARED_TOKEN` с тем же
   значением — одной переменной хватает сразу на обе функции
3. Пересоздайте деплой

Это не настоящая защита (значение видно в исходном коде страницы), но отсекает
ботов, которые нашли адрес функции и стучатся в неё напрямую, не открывая сам
сайт.

(Встроенный в Netlify rate limiting по IP пробовали подключить, но он требует
V2-формата функции, который оказался ненадёжным при обычном перетаскивании
папки — пришлось откатить ради стабильности.)
